# MyKeys 2.0 · 产品与交互设计文稿

日期：2026-09-12  
状态：可实施设计稿；配套 HTML 原型已完成。

## 1. 产品定义

MyKeys 是一个完全本地运行的个人 API Key 保险库。它不试图成为云端协作平台，也不读取厂商余额或替用户调用第三方接口。2.0 只把一件事做得足够可靠：让用户安全地保存秘密，并在真正需要时快速、可控地取出。

产品的第一印象不是“功能很多”，而是“我的秘密在这里是可理解、可控制的”。因此首页只有「存入密钥」与「取用密钥」两个主入口；安全选项放在设置中，说明必须使用普通人能准确理解的语言。

## 2. 已确认的 2.0 决策

- 后台生成数据加密密钥，不向用户展示，也不把它包装成第二个密码或恢复码。
- 用户只需记住主密码；系统不保存可还原的主密码。
- 连续五次密码错误不销毁数据，改为延迟解锁，并逐步增加等待时间。
- 主动销毁保险库必须输入确认文字，且明确说明不会撤销厂商侧仍然有效的 API Key。
- 解锁策略提供四种模式：每次启动、信任本机 72 小时、使用系统凭据自动解锁、无需主密码。
- 关闭主密码是显式降级：需要当前主密码确认，旧的启动解锁方式立即失效。
- “取用时再次验证”作为独立开关；验证后提供 5 分钟授权窗口。
- 修改主密码只重新包装数据密钥，不逐条重新加密全部 API Key。

## 3. 产品原则

### 3.1 本地优先

MyKeys 不要求账户，不提供云同步，不加载远程脚本、字体或图片，不记录遥测。厂商 Logo 在构建时内置。应用关闭后，不应存在可供前端恢复的明文业务缓存。

### 3.2 秘密默认不可见

API Key 在存入时短暂接收明文，之后只显示遮蔽值。查看完整值是一项短时动作，10 秒后自动隐藏；复制是一项可审计的本机会话动作，应用在 30 秒后、且剪贴板仍为本次写入值时尝试清除。

### 3.3 安全必须可理解

界面不使用“军事级”“绝对安全”“无法破解”等不可验证的承诺。系统凭据自动解锁意味着安全边界部分转移到操作系统账户；MyKeys 应在用户选择该模式时直接说明这一点。

### 3.4 不用惩罚性设计保护数据

密码错误不能触发自动销毁。失败次数连续增加时，采用逐步延迟、清晰提示和错误分类。I/O、系统凭据或文件损坏不能算作密码错误。


## 5. 首次使用

### 5.1 欢迎

主标题为「你的密钥，只在这里。」正文直接解释本地保存、无账号、无云端、无遥测。唯一主操作为「开始设置」。不在此页讲算法细节，以免把首次使用变成安全说明书。

### 5.2 创建主密码

要求输入两次，实时显示是否一致。前端只提供辅助提示，最终强度与一致性验证由 Rust 核心执行。密码不能静默截断或自动去除首尾空格；如产品决定禁止空格，应明确提示而不是自行修改。

后台同时生成随机数据密钥 DEK。DEK 不显示给用户，不称为“专属隐藏秘钥”，不承担恢复码功能。

### 5.3 选择解锁方式

提供三项互斥选择：

- 每次启动：默认选项，每次启动输入主密码。
- 信任本机 72 小时：在有效期内通过受保护的本机凭据解锁，满 72 小时强制验证主密码。
- 系统凭据：使用 macOS Keychain、Windows DPAPI 或 Linux Secret Service。安全设施不可用时禁用该项，不能退回明文文件。
- 无需主密码：不设置主密码，打开即用。保险库仍是密文，数据密钥由本机系统凭据保管；取用验证强制关闭。

首次引导的「创建主密码」步骤提供「不设置主密码」入口，选择后跳过解锁方式与取用验证两步，直接进入完成页。

### 5.4 取用验证

这是独立于启动解锁的开关。开启后，显示或复制完整密钥前验证主密码；成功后建立 5 分钟授权。应用锁定、系统锁屏或进程退出时立即取消授权。

### 5.5 完成

说明保险库已经准备好，并再次明确 MyKeys 不会联网验证 API Key。进入首页后不强迫用户立即填写记录。

## 6. 日常解锁

解锁页只包含 Logo、主密码输入、解锁按钮和忘记密码入口。一次主动提交且密码错误才增加失败次数：

| 连续失败 | 行为 |
| --- | --- |
| 1～2 次 | 显示通用错误，不泄露内部文件状态 |
| 第 3 次 | 等待 5 秒后允许重试 |
| 第 4 次 | 等待 30 秒后允许重试 |
| 第 5 次及以后 | 每次等待 5 分钟；不删除数据 |

成功使用主密码解锁后清零。系统凭据解锁不清零。计数需要持久化和完整性保护，但不能宣称能阻止管理员恢复旧状态或复制保险库离线试错。

忘记密码页说明没有找回机制。用户可以主动销毁保险库并重新开始，但必须完成明确的文字确认。

## 7. 首页

首页只呈现「存入密钥」和「取用密钥」两个等权主入口。设置通过内部侧栏进入，不增加第三张首页卡片。首页不显示记录总数、最近使用、推荐厂商或安全评分，避免在锁定策略出现疏漏时泄露信息，也避免制造无价值的数据装饰。

## 8. 存入密钥

首屏字段只有名称、厂商与 API Key；到期时间、权限、备注和自定义字段收入「添加详细信息」。

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，1～80 字符，允许重名 |
| 厂商 | 内置厂商或自定义名称 |
| API Key | 必填，按原样保存，不擅自裁剪 |
| 到期时间 | 可选；未设置不等于永久有效 |
| 权限 | 可选文本列表，`全部权限` 与具体权限不可混用 |
| 备注 | 可选纯文本，不执行 HTML |
| 自定义字段 | 可选，限制数量和长度 |

保存过程禁用重复提交。只有加密文件完成同步写入和原子替换后，才能显示「已加密保存」。成功后立即清空 API Key 输入，避免旧秘密被重复保存。

离开存在未保存内容的页面时，提供「继续编辑」「放弃」「保存」三项，不静默丢失。

## 9. 取用密钥

桌面宽度下使用左侧列表、右侧详情。列表支持名称、厂商与备注搜索，并按厂商过滤。搜索只在解锁后的内存中执行。

每行显示厂商 Logo、记录名称、厂商和到期状态。状态必须同时使用颜色与文字：可用、即将到期、已过期、已停用。已过期记录继续允许查看与复制，但明确警示，不自动删除。

完整密钥默认不出现。点击「显示」后展示 10 秒；点击「复制」不要求先渲染完整值到页面，生产实现优先由 Rust 核心直接写入剪贴板。第三方剪贴板历史工具可能保留内容，界面不能承诺绝对清除。

## 10. 设置

### 10.1 解锁设置

可修改三种启动解锁方式。涉及降低验证频率的修改必须先验证主密码；系统凭据写入或删除成功后才能更新界面状态。

### 10.2 修改主密码

验证旧密码，生成新盐与新 KEK，重新认证加密已有 DEK，并事务性替换保险库头部。无需逐条重新加密业务记录，也不显示“正在处理第 N 个 API Key”的虚假迁移进度。

### 10.3 立即锁定

清理当前会话中的密码、KEK、DEK 与已解密业务数据，撤销 5 分钟取用授权，返回解锁页。前端切页本身不是锁定，所有敏感 IPC 仍须由核心检查会话。

### 10.4 销毁保险库

用户输入「删除全部数据」后调用统一销毁流程：冻结新操作、移除受保护的免密凭据、清理会话秘密、删除保险库和受控临时文件、核对结果。部分失败必须显示「清理未完成」并允许重试，不能虚报成功。

销毁仅覆盖 MyKeys 管理的本机数据，不保证 SSD、快照、备份或用户自行复制文件的物理不可恢复，也不会撤销厂商侧 API Key。

## 11. 数据与加密架构

延续 v1 的信封加密方案：

1. 系统密码学安全随机源生成 32 字节 DEK、随机 salt、nonce 和 `vault_id`。
2. 主密码经 Argon2id 派生 32 字节 KEK；参数在目标机器测试后锁定到格式版本。
3. 使用 XChaCha20-Poly1305 以 KEK 认证加密 DEK。
4. 使用 DEK 认证加密完整业务数据；名称、厂商、权限、备注和时间均不建立明文索引。
5. 格式头中的版本、算法、KDF 参数与 `vault_id` 纳入认证附加数据；在使用未认证参数前先检查资源上限。

生产实现继续采用 Tauri 2、Rust 核心与原生 TypeScript 页面。前端不拥有任意文件系统、Shell 或网络权限。内容安全策略禁止远程脚本与导航。

### 11.1 系统凭据的访问约束

解锁路径对系统凭据必须**只读**。macOS 在写入条目时会重新做一次 ACL 鉴权，而条目 ACL 记录的是创建它的那个二进制身份；开发期的 ad-hoc 签名每次重建都会变，于是"每次启动回写一次凭据"会演变成"每次启动弹一次钥匙串授权对话框"。

凭据只在四种时机写入：初始化保险库、修改主密码、切换解锁模式、销毁保险库。解锁只读取，不刷新 `last_used_at`；该字段仍参与系统时间回拨校验，只是不再更新。

## 12. 动效规范

- 页面前进：旧页轻微向左收束，新页由右侧 34px 进入，420ms。
- 页面返回：方向相反，保留空间关系。
- 初始化步骤：内容自下方 12px 淡入，进度点连续伸缩。
- 弹层：背景 220ms 淡入并轻微模糊，面板由 97% 放大至 100%。
- 操作卡：悬停最多上移 4px，不使用持续漂浮动画。
- 完成状态：绿色确认标记只播放一次弹性较弱的缩放动画。
- 尊重 `prefers-reduced-motion`，将所有动画压缩为近乎即时状态变化。

动效不应延迟安全操作的真实完成状态。保存、锁定和销毁的成功提示必须以后端确认结果为准。

## 13. 视觉与无障碍

整体采用 Apple 式留白、低层级边界和清晰字重。品牌蓝紫渐变只用于 Logo；按钮和状态点使用蓝、绿、橙、红等功能色。

- 默认窗口建议 1040 × 720，最小 680 × 560。
- 正文 14～15px，页面标题 32px，欢迎主标题 44px。
- 主要点击区域高度不低于 42px。
- 键盘焦点使用高对比蓝色外环，不因连续圆角裁切。
- 密码显示状态、保存结果和错误信息需要屏幕阅读器播报。
- 状态不可只靠颜色；图标、文字和颜色共同表达。
- 小窗口下取用页切换为列表优先，详情作为下一层页面，而不是把双栏强行压窄。

## 14. 原型边界

HTML Demo 展示完整前端结构、点击路径、动画和反馈，但不执行真实加密、不保存真实秘密、不操作系统凭据库，也不真正读写剪贴板。演示密码接受任意非空内容；所有 API Key 均是明确的样例字符串。

## 15. 实施阶段与验收

### 阶段 A：保险库核心

完成格式版本、KDF、认证加密、原子保存、文件锁、会话状态和错误分类。测试随机源失败、密文篡改、恶意 KDF 参数、断电与并发写入。

### 阶段 B：界面接入

将原型状态机替换为最小 IPC 命令，完成存、取、修改、删除、锁定和错误恢复。在这一阶段结束前禁止导入真实 API Key。

### 阶段 C：平台安全设施

接入 macOS Keychain、Windows DPAPI 与 Linux Secret Service。Linux 缺少安全凭据服务时禁用免密。完成休眠、系统锁屏和空闲锁定测试。

### 阶段 D：发布

分别在 macOS、Windows 与明确版本的 Ubuntu/Debian 上完成干净环境安装、升级和卸载验证。记录真实包体、内存、KDF 延迟与平台依赖，不在测量前承诺指标。

### 必要验收

- 锁定文件、临时文件和错误日志均不出现业务明文。
- 锁定后所有敏感 IPC 拒绝读取、复制或修改。
- 密码错误不会删除数据，重启不会清零连续失败计数。
- 修改主密码中断后仍能以旧状态或新状态之一完整打开，不产生半状态。
- 系统凭据写入或删除失败时，界面不显示错误的解锁模式。
- 保存失败不覆盖最后一份有效保险库。
- 销毁只操作固定受控路径，部分失败不显示成功。
- 到期状态覆盖当前时区、休眠恢复和系统时间变化。
- Windows、macOS 与 Linux 的键盘导航、焦点和减少动态效果均通过验证。
- 关闭主密码后，原主密码不再能打开保险库；无主密码时取用验证无法启用。

## 16. 无主密码模式

### 16.1 定位

「能打开这台电脑的人，就是自己信任的人。」该模式面向个人设备：接受安全边界整体转移到操作系统账户，换取打开即用。它不改变产品定位，只把解锁成本降到零。

### 16.2 不改变的约束

| 约束 | 说明 |
| --- | --- |
| 文件仍是密文 | 保险库文件沿用同一格式与认证头，不出现明文落盘 |
| 数据密钥不落盘 | DEK 只经系统凭据取出，不写入保险库文件 |
| 参数受认证保护 | 版本、vault_id 与 KDF 参数继续纳入 AAD |

关闭主密码时，DEK 会用一个新的随机口令重新包装，该口令不写入任何位置。这一步是实质性的：关闭之后，原主密码再也不能打开这份文件。

### 16.3 明确不能承诺的事

- 能运行在同账户下的程序，可以读取系统凭据并打开保险库。
- 系统凭据被重置、迁移或设备更换后，保险库无法恢复。
- 备份、快照或自行复制的文件，同样只受系统凭据保护。

### 16.4 恢复路径

设置页的「设置主密码」是唯一恢复手段：它要求保险库当前已解锁，把 DEK 重新用新主密码包装，并切换回三种带密码的解锁模式之一。它能在钥匙串仍然可用时提前建立退路，无法在钥匙串已经丢失后补救。

### 16.5 界面义务

- 选择该模式前必须说明安全边界转移与不可恢复风险。
- 免密状态下隐藏「取用时再次验证」，因为已无密码可验证。
- 免密状态下不提供「立即锁定」，窗口失焦与闲置都不会把保险库退回密码页。
- 设置页持续显示「打开即用，不需要主密码」，不使用「已安全」类措辞。

### 16.6 会话不回落

免密保险库的数据密钥随时可从系统凭据重新取出，因此锁定它既不能提供有效保护，又会把窗口留在"要求一个不存在的密码"的死路上。为此：

| 行为 | 有主密码 | 无需主密码 |
| --- | --- | --- |
| 窗口失焦 | 清除会话，回到解锁页 | 保留会话 |
| 闲置 5 分钟 | 清除会话，回到解锁页 | 保留会话 |
| 立即锁定 | 可用 | 隐藏，接口返回明确错误 |

这是有意的取舍：免密模式下内存中的会话本就不构成额外防线，而同账户程序可以直接读取系统凭据。真正需要"离开即锁定"的使用者应选择带主密码的模式。
