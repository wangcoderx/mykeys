# MyKeys 本地 API Key 管理器 · 设计方案 v1

日期：2026-09-11  
状态：产品与技术设计草案；尚未实现应用、下载 Logo 或完成安全审计。

## 1. 从第一性原理定义产品

用户需要可靠地存下 API Key，并在需要时快速取出。软件只围绕这两件事组织界面：打开后的业务首页只有「存」「取」两个按钮。第一次启动必须先完成主密码设置；需要密码时，在进入首页前解锁。

安全优先于包体积，简单优先于功能数量。程序完全本地运行，没有账号、云端服务、遥测、在线字体、远程脚本和常驻服务。Logo 在开发阶段获取并内置，日常使用无需联网。

第一版支持单用户、单保险库、多条 API Key。暂不做云同步、多人共享、浏览器插件、余额查询、自动续期和厂商 API 调用。

## 2. 已确认需求与必要修正

| 需求 | v1 设计 |
| --- | --- |
| 首次设置主密码 | 输入两次确认，不保存密码原文 |
| 后台生成随机密钥 | 使用操作系统密码学安全随机源生成 256 位数据密钥 |
| 可关闭启动密码 | 支持，通过系统凭据库授权本机自动解锁，默认关闭免密 |
| 忘记密码 | 无找回、无后门；提供「删除全部数据并重新开始」 |
| 连续输错 5 次 | 销毁当前应用管理的保险库及解锁凭据 |
| 内部页面毁机 | 名称用「销毁保险库」，删除本应用密钥数据，不擦除电脑 |
| 跨平台 | 同一源码，分别构建 Windows、macOS、Linux 安装包 |

这不是非对称加密。非对称加密涉及公钥和私钥；本方案使用对称认证加密与信封加密：随机数据密钥保护数据，主密码派生的密钥保护数据密钥。两层密钥不代表两个独立认证因素。

时间戳仅用于创建、更新、过期时间，不用于生成秘密。可预测的数据无法提供可靠的密钥熵。

**免密模式的明确边界：**忘记主密码时，已经授权的本机仍然可以自动读取保险库。只有要求主密码且不存在免密凭据时，才能做到不知道密码便无法正常解锁。两个模式不能同时满足相反的要求。界面必须在关闭启动密码时说明这一点。

“后台知道主密码”调整为“本地核心在用户输入时短暂处理密码，之后清理”。不持久保存可还原的主密码，也不通过隐藏文本假装保密。

## 3. 安全边界

重点保护：丢失或被复制的保险库文件、磁盘上的明文泄露、文件篡改、误操作暴露。

无法承诺：已被恶意软件控制的系统、管理员读取进程内存、键盘记录、截图、第三方剪贴板历史、系统快照与备份副本、离线攻击者遵守应用的试错计数。

免密模式将主要访问边界转移到操作系统账户。别人能够使用该账户并通过系统凭据访问检查时，可能可以打开保险库。系统凭据库不是抵御同账户所有恶意程序的绝对隔离层。

## 4. 加密与文件结构

### 4.1 加密流程

1. 首次建立保险库，生成随机 vault_id、至少 16 字节随机盐及 32 字节数据密钥 DEK。
2. 用户主密码通过 Argon2id 派生 32 字节包装密钥 KEK。候选起点为 64 MiB、3 次迭代、4 路并行；在目标机器上测量后确定参数，写入格式版本，不静默降低安全强度。
3. 使用 XChaCha20-Poly1305，以 KEK 认证加密 DEK。
4. 使用 DEK 认证加密整个业务数据集合。名称、厂商、权限、备注及时间全部在密文内部。
5. 每次加密使用新的随机 24 字节 nonce，包装与数据加密使用不同 nonce；随机源失败则拒绝保存。
6. 格式版本、vault_id、算法及 KDF 参数等相关头部字段纳入认证附加数据。读取未认证的 KDF 参数前先做资源上限校验，防止恶意文件诱发内存耗尽。

采用成熟库的高层接口，不自行实现密码算法。具体 Rust 库及版本在实现时锁定并审查维护状况与依赖；算法可靠不等于集成已经安全。

### 4.2 持久化内容

```text
应用数据目录/
  vault.mykeys       格式头 + 被包装的 DEK + nonce + 业务密文及认证标签
  security-state    保险库标识、失败计数、销毁状态；无业务明文
  settings          非敏感界面偏好
```

格式头不可避免暴露格式、KDF 配置、随机标识、文件大小等信息。不开明文索引，不将 API Key 写入 SQLite、localStorage、日志、崩溃报告或临时文本。

v1 采用整库加密文件，适合个人规模；拟定上限 5,000 条、解密后 20 MiB，超限明确拒绝。限制备注与自定义字段长度。该上限是设计值，需性能验证。

保存使用同目录加密临时文件、同步写入和平台适配的原子替换；成功落盘后才显示「已保存」。应用单实例和文件锁阻止并发覆盖。崩溃恢复只处理加密文件，销毁流程涵盖临时与恢复文件。

### 4.3 解锁与修改密码

输入密码后派生 KEK，以成功解包 DEK 作为认证依据，再验证并读取数据密文。错误提示不泄露内部细节。损坏、格式不支持、I/O 异常和凭据库异常不能简单归类为密码错误。

密码包装认证失败仍可能来自包装区域被篡改，无法总是与错误密码区分；五次删除策略因此存在被恶意触发的数据丢失风险，不能描述成可靠防破解机制。

修改主密码必须验证旧密码，生成新盐与 KEK 并重新包装 DEK，事务性写入。修改完成才清理旧会话材料；遗留副本不随改密失效。怀疑数据密钥泄露时需要轮换 DEK 并重加密，同时到厂商撤销或轮换 API Key。

## 5. 启动密码与免密打开

默认「打开时要求主密码」开启。关闭它需要验证主密码，并说明本机授权后的可读性。

免密开启时，将 DEK 作为解锁秘密交给系统凭据保护设施，保险库中仍保留主密码包装路径。macOS 使用本机 Keychain 条目并禁止同步；Windows 使用当前用户作用域的 DPAPI 保护材料；Linux 使用 Secret Service。Linux 未提供可用安全凭据服务时，禁用免密，不能回退到明文文件。

系统可能要求账户认证，因此不能承诺每台机器都无提示。凭据访问失败时退回主密码输入；这些错误不增加密码失败计数。

重新开启启动密码：验证主密码，删除免密凭据，确认删除成功后才切换状态。失败则保留准确的模式提示。启动不能仅信任一个可编辑的设置布尔值绕过核心认证。

所有数据操作由 Rust 核心检查会话状态。前端隐藏页面不是权限控制。手动锁定、休眠、系统锁屏或闲置 5 分钟清理会话；手动锁定后当前进程要求主密码，不立即自动解锁。免密模式下重启应用仍可自动解锁，这一限制必须如实说明。

## 6. 五次失败与忘记密码

### 6.1 计数规则

- 同一保险库所有主密码验证入口共享连续失败计数，包括解锁和修改安全设置。
- 一次主动提交并完成的密码认证失败计为一次；空输入、取消、系统错误不计入。
- 正确验证主密码后归零；免密解锁不归零。关闭窗口、重启应用不归零。
- 后端串行执行验证，禁用提交期间的重复点击；计数必须落盘后才返回结果。
- 第 1～4 次显示剩余次数；第 4 次明确提示「再输错 1 次将删除当前保险库全部数据」。
- 第 5 次失败立即进入销毁流程，不再弹第二次确认。这项行为在首次设置时清晰告知。
- 持久化计数失败或状态异常时停止认证并显示修复信息，不默认为 0，也不把技术故障当成第五次失败。

计数状态做完整性保护，保护材料与保险库绑定并由平台安全存储管理。缺少可信保护设施时必须明确降低的保证；状态认证也不能防止管理员恢复旧副本或修改程序。攻击者复制文件后可离线试密码，仍依赖密码强度与 Argon2id 防护。

### 6.2 忘记密码

密码页提供「忘记密码」文本入口，解释：没有密码找回功能；可删除当前保险库并重新设置。点击后显示记录无法恢复的说明，输入「删除全部数据」后执行销毁；不要求旧密码，否则忘记密码时无法完成重置。

这也意味着能操作登录界面的人能够主动销毁本地数据。该行为是本产品按用户要求做出的取舍。

v1 不自动创建历史备份，也不提供导出功能，减少销毁对象和恢复路径。用户自行复制的文件、系统备份与快照仍可能存在；应用无法让它们自动失效。

## 7. 销毁保险库

入口放在「存 / 取」内部页面右上角更多菜单的危险操作区，不占首页第三个按钮。

主动销毁时展示范围，输入确认文字再执行；五次密码错误走同一个后端销毁入口，但不再确认。

执行顺序：

1. 标记正在销毁，拒绝新操作，关闭展示与复制入口。
2. 删除该 vault_id 的免密凭据及相关受保护材料，尽力清理内存中的 DEK、KEK、密码与明文。
3. 删除保险库、包装密钥材料、临时文件、应用管理的恢复文件、安全状态和保险库关联设置；仅使用固定受控路径，不递归删除用户目录。
4. 剪贴板仍是本应用写入内容时尽力清空，不覆盖用户后来复制的其他内容。
5. 检查删除结果；全部完成才显示「本机保险库已清空」，返回首次设置。

进程中断后，启动优先恢复未完成的销毁，不允许自动解锁。某文件或系统凭据删除失败则显示「清理未完成」及重试入口，不虚报成功。

主密码原文原本就不保存，销毁的是其派生保护材料、随机数据密钥的可访问副本和加密数据。对于 SSD 磨损均衡、快照、交换区及外部副本，不能保证物理不可恢复；密码可重新推导包装密钥，所以遗留的完整保险库副本仍可能被正确密码打开。不能把删除包装密钥文件等同于全设备密码学擦除。

销毁不等于撤销：厂商侧 API Key 仍可能有效，必须到对应厂商平台撤销。

## 8. 数据模型

| 字段 | 类型与规则 |
| --- | --- |
| id | 随机唯一标识，不使用时间戳当秘密 |
| name | 必填，1～80 字符，允许重名 |
| provider_id / provider_name | 内置厂商标识或自定义名称 |
| provider_logo_id | 指向随软件内置的本地图标；不存远程加载 URL |
| secret | 必填，输入明文后在核心加密；默认遮蔽，不擅自裁剪内容 |
| expires_at | 可空；空代表「未设置」，不声称厂商永久有效 |
| permissions | 独立的 -1 表示全部权限，否则为用户输入的字符串列表；混用则拒绝 |
| created_at | 应用自动写入 UTC 时间 |
| updated_at | 实际修改后自动更新，查看和复制不更新 |
| notes | 可选纯文本备注，不执行 HTML |
| custom_fields | 可选键值列表，随整库加密，限制数量与长度 |

用户不需要填写「加密后的密钥」：填写原始 API Key，软件负责加密保存。取用时显示遮蔽内容，按需短暂显示或复制；密文不作为日常展示内容。

权限和过期时间属于用户记录，软件不与厂商核验，也不授予或修改实际权限。

## 9. 页面与操作

### 9.1 首页

首次设置或成功解锁后，居中并列「存」「取」两个主要按钮。留白承担布局，不加统计卡、欢迎横幅、推荐服务和装饰图表。

### 9.2 存

左上角为「存 / 取」分段切换。默认显示名称、厂商、API Key；到期、权限、备注及自定义字段放在可展开的详细信息区。保存成功后短提示「已加密保存」，清空 API Key 输入；其余字段是否保留按连续录入体验实现，不能重复保存旧秘密。

切换模式时有未保存编辑则提供保存、放弃和继续编辑，不能悄悄丢弃。

### 9.3 取

左上角保留相同切换。搜索按名称、厂商、备注过滤，全部在已解锁内存中进行。列表行显示 Logo、名称、厂商、到期状态；选择记录后显示详情。支持编辑和单条删除，单条删除需要确认。

API Key 默认遮蔽，提供「显示」「复制」。显示 10 秒后隐藏；复制 30 秒后仅在剪贴板仍为本次内容时尝试清空。复制优先由 Rust 核心执行，不为了复制先将秘密传到页面。剪贴板失败则如实提示，历史记录软件可能仍保留内容。

### 9.4 过期提醒

未设置、有效、7 天内到期、已过期四种状态，文字与颜色同时表达。边界以 now >= expires_at 为已过期。日期输入明确采用当前时区当日结束时间并转换 UTC；同时允许设置具体时间。

解锁、窗口回到前台、恢复休眠与跨越最近到期时刻时重新计算。系统时间变动后重新计算；离线设备无法保证时钟可信。

已过期条目保留并提示，不自动删除，不禁止复制。关闭应用不运行后台提醒；锁定状态不泄露记录名称或数量。

## 10. 视觉规范

方向为 Apple 式留白、克制层级与鲜明局部色彩。首页只保留两个操作，内部页面以行列表和清晰排版组织，避免每个字段都套卡片。

建议初稿：背景 #F5F5F7、内容面 #FFFFFF、正文 #1D1D1F、强调蓝 #007AFF；到期警示使用可读的橙红色文字与淡色底。最终颜色须检查对比度，不能只靠颜色传递状态。

字号建议正文 14～15 px、页面标题 24 px、首页操作 28 px；8 px 间距节奏，主要内容边距 32 px。默认窗口 880×620，最小 640×480，小窗口表单单列。遵循系统字体回退，不捆绑 Apple 专属字体到其他平台。

**圆角采用连续曲率的设计意图，而非任意统一 border-radius。** 定义共享连续圆角形状组件，用经过视觉验证的路径或遮罩近似，在不同 WebView 中保持一致；保留正常焦点环和命中区域。输入框、按钮、面板分别按尺寸定义曲率，内外嵌套保持视觉同心。跨平台近似不能宣称与 Apple 私有几何实现完全相同。

拟定按钮高 48 px、输入框高 44 px，面板与按钮使用独立形状参数。动效 120～180 ms，只用于状态反馈，尊重系统减少动态效果选项。提供键盘导航、明确焦点、屏幕阅读器标签和密码可见状态播报。

### Logo 资产计划

首批候选：OpenAI、Anthropic、Google Gemini、DeepSeek、阿里云、腾讯云、火山引擎、AWS、Azure、GitHub。实施阶段从官方品牌资料或官方仓库获取，逐项保存来源 URL、原文件、校验值和使用说明。

优先官方彩色版本，品牌只有单色版本时不擅自着色。显示容器可以采用淡彩背景。外来 SVG 必须去除脚本、外部引用与事件处理，或在构建时转成静态 PNG。缺少可用资产时显示厂商文字，不冒充已获得官方 Logo。本次只交付方案，资产下载与核验列入下一阶段。

## 11. 技术与发布选择

建议 Tauri 2 + Rust 核心 + TypeScript 原生页面，不引入大型 UI 组件库。它复用系统 WebView，有利于缩小分发体积，但并非所有系统零依赖。

Rust 管理加密、文件、状态、验证和剪贴板；前端负责界面。IPC 命令最小化，所有敏感命令检查会话与参数；显式配置 Tauri 权限。内容安全策略禁止外部网络和远程代码，不给页面通用 shell、任意路径读写或远程导航权限。

性能目标属于待验证指标：应用自身压缩分发体积争取 20 MB 内（不含系统运行时），空闲内存争取 100 MB 内，解锁目标约 0.5～1.5 秒。KDF 峰值内存单独计量，不为追逐体积或速度降低加密保护。使用目标机器记录实测结果，再确定承诺。

「一键」指准备好工具链后，用统一构建入口或 CI 工作流分别产出三平台制品，不是一份可执行文件在所有系统运行。

| 平台 | 交付方式及限制 |
| --- | --- |
| macOS | DMG，拖入应用目录；正式分发需要签名与公证流程 |
| Windows | 安装 EXE，检测 WebView2；缺少运行时需安装，离线完整包会更大 |
| Linux | 优先支持明确版本的 Ubuntu/Debian，提供 deb，AppImage 另行验证；WebKitGTK 等依赖需实测 |

每个平台使用相应构建环境；macOS ARM64/x64、Windows x64、Linux x64 纳入首批目标。签名证书与 CI 配置在发布阶段准备。普通用户不需要 Rust 或 Node.js，开发者需要工具链。无已验证的平台不得宣称支持。

## 12. 验收与实施顺序

阶段 A：确认本文默认行为，制作首页、存、取、解锁和销毁的可交互视觉稿；获取并核验 Logo。

阶段 B：先实现并验证 Rust 保险库核心，再接界面；在加密、事务写入、会话与销毁完成前不导入真实 API Key。

阶段 C：完成系统凭据适配和三平台打包，发布前进行独立安全检查。

必要验收：

- 新安装必须设置主密码，首页业务入口只有存和取。
- 所有业务字段在锁定文件中不出现明文；测试包含临时文件与错误日志扫描。
- 加密往返、错误密码、密文篡改、恶意头部、随机源失败均有明确行为。
- 第五次失败触发同一销毁流程，重启不重置计数，正确密码归零，自动解锁不归零。
- 销毁中断后继续清理，文件或凭据删除失败不得显示成功；使用隔离测试目录验证，不接触真实密钥。
- 免密开关与系统凭据删除结果一致；Linux 凭据服务不可用时无不安全回退。
- 锁定后调用 IPC 无法读取、复制或修改记录；远程脚本、用户备注和恶意图标不能执行代码。
- 断电模拟与并发写入不会产生半份保险库；保存失败不丢失原文件。
- 到期边界、时区、休眠恢复和系统时钟变化有测试。
- 三平台真机或干净虚拟机完成安装、存取、锁定、免密、清库验收并记录包体与内存。
